# Windows Security

Windows has a **vast attack surface** due to many built-in apps, features, and settings — easily misconfigured even when fully patched. Microsoft has added hardening features over the years, but the system still has many abusable components.

---

## Core Security Principles

- Applies to **users, networked computers, threads, and processes**.
- Designed to **minimize risk of unauthorized access**.
- Goals: control access and authentication within the system.

---

## Security Identifier (SID)

- Every **security principal** (user, group, computer) has a unique **SID**.
- Automatically generated by Windows — distinguishes identical users.
- Stored in the **security database** and added to the user's **access token**.
- SID format includes **Identifier Authority** + **Relative ID (RID)**; in AD domains, also includes **domain SID**.

```powershell
# View current user's SID
whoami /user
```

**SID Pattern:**

```
(SID)-(revision level)-(identifier-authority)-(subauthority1)-(subauthority2)-(etc)
```

| Part | Meaning | Description |
| --- | --- | --- |
| **S** | SID | Identifies string as a SID |
| **1** | Revision Level | Always 1 (never changed) |
| **5** | Identifier Authority | 48-bit string identifying the authority that created the SID |
| **21** | Subauthority1 | Identifies user's relation/group to the authority |
| **674899381-4069889467-2080702030** | Subauthority2 | Which computer/domain created the number |
| **1002** | Subauthority3 (RID) | Distinguishes accounts — normal user, guest, admin, etc. |

> Example: `S-1-5-21-674899381-4069889467-2080702030-1002`
>

## SAM and Access Control Entries (ACE)

| Component | Purpose |
| --- | --- |
| **SAM** | Grants rights to a network to execute specific processes |
| **ACE** | Managed by Access Control Lists (ACLs) — defines who has access to files/processes |
| **DACL** | Discretionary ACL — permissions on securable objects |
| **SACL** | System ACL — auditing rules |
| **Access Tokens** | Validated by **Local Security Authority (LSA)** — contain SID + other security info |

> Understanding these is essential for **privilege escalation**.
>

## User Account Control (UAC)

- Security feature to **prevent malware from running/manipulating processes**.
- **Admin Approval Mode**: prompts before installing software or making system-wide changes.
- **Standard user**: execution denied or admin password required.
- **Consent prompt**: interrupts scripts/binaries until user confirms.

```
# Typical flow:
Admin action requested → UAC prompt → User confirms → Elevation granted
Standard user action → Denied or admin creds required
```

## Registry

- **Hierarchical database** critical for Windows OS + applications.
- Stores **low-level settings** (computer-specific + user-specific).
- Open via: `regedit` (command line or Start menu search).

### Registry Value Types

| Value | Type |
| --- | --- |
| **REG_BINARY** | Binary data |
| **REG_DWORD** | 32-bit number |
| **REG_DWORD_LITTLE_ENDIAN** | 32-bit little-endian |
| **REG_DWORD_BIG_ENDIAN** | 32-bit big-endian |
| **REG_EXPAND_SZ** | Null-terminated string with env variables (e.g., `%PATH%`) |
| **REG_LINK** | Symbolic link target path |
| **REG_MULTI_SZ** | Sequence of null-terminated strings |
| **REG_NONE** | No defined value type |
| **REG_QWORD** | 64-bit number |
| **REG_QWORD_LITTLE_ENDIAN** | 64-bit little-endian |
| **REG_SZ** | Null-terminated string |

### Root Keys

- Start with **HKEY**; abbreviated (e.g., `HKLM` = `HKEY_LOCAL_MACHINE`).
- **HKLM** contains: SAM, SECURITY, SYSTEM, SOFTWARE, HARDWARE, BCD.
- Loaded into memory at boot (except HARDWARE — dynamically loaded).

### Registry File Locations

```powershell
# System registry files
C:\Windows\System32\Config\

# User-specific hive (HKCU)
C:\Users\<USERNAME>\Ntuser.dat
```

```powershell
# List registry files
ls C:\Windows\system32\config

# List hidden files in user folder (shows NTUSER.DAT)
gci -Hidden C:\Users\bob
```

### Run and RunOnce Keys (Persistence)

- Hives that load software when OS starts or user logs in.
- Useful for **maintaining access**.

```
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunOnce
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunOnce
```

```powershell
# Query HKLM Run key
reg query HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run

# Query HKCU Run key
reg query HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

## Application Whitelisting

| Approach | Description |
| --- | --- |
| **Whitelist** | Only approved software allowed — "zero trust" principle |
| **Blacklist** | Only harmful/disallowed software blocked — all else allowed |
- Whitelisting recommended by **NIST** (especially high-security environments).
- Implement in **audit mode** first to avoid blocking necessary apps.
- Less overhead — admins only specify what's allowed.

---

## AppLocker

- Microsoft's **application whitelisting solution** (Windows 7+).
- Granular control over: **executables, scripts, Windows installers, DLLs, packaged apps**.
- Rules based on: **publisher, product name, file name, version, file path, hash**.
- Can apply to **security groups or individual users**.
- Deploy in **audit mode** first.

---

## Local Group Policy

- **Group Policy** = set, configure, adjust settings.
- **Domain environment**: pushed from Domain Controller to domain-joined machines via **GPOs**.
- **Local Group Policy**: defined on individual machines (works in domain + non-domain).

```
# Open Local Group Policy Editor
gpedit.msc
```

**Editor structure:**

```
Local Computer Policy
├── Computer Configuration
└── User Configuration
```

**Use cases:**

- Lock down individual computer policy
- Enable **Credential Guard** (Turn On Virtualization Based Security)
- Fine-tuned account auditing
- Configure **AppLocker**

> Credential Guard = protects against credential theft by isolating **LSA process**.
>

## Windows Defender Antivirus

| Feature | Description |
| --- | --- |
| **Real-time protection** | Protects from known threats in real-time |
| **Cloud-delivered protection** | Works with automatic sample submission to upload suspicious files |
| **Tamper Protection** | Prevents security settings from being changed via Registry, PowerShell, or Group Policy |
| **Controlled folder access** | Built-in Ransomware protection |
| **Exclusion list** | Files/folders not scanned (e.g., pentest tools) |

```powershell
# Check which protection settings are enabled
Get-MpComputerStatus | findstr "True"
```

**Key points:**

- Ships free with Windows; first released as downloadable anti-spyware for XP/Server 2003.
- Prepackaged since **Windows Vista / Server 2008**.
- Renamed to **Windows Defender Antivirus** with Windows 10 Creators Update.
- Does well in monthly detection rate tests vs. paid solutions.
- Picks up payloads from **Metasploit** and unaltered **Mimikatz**.
- Not a silver bullet — part of **defense-in-depth** strategy.

## Answer to Lab Questions

**Q1: Find the SID of the `bob.smith` user.**

```powershell
# On the target machine (RDP in first)
whoami /user

# Or query a specific user
wmic useraccount where name='bob.smith' get sid

# Or via PowerShell
Get-LocalUser -Name "bob.smith" | select Name,SID

# Or via CMD
wmic useraccount get name,sid
```

> RDP to `10.129.208.78` (ACADEMY-MISC-WS01) with user `htb-student` / password `Academy_WinFun!`
> 

**Q2: What 3rd party security application is disabled at startup for the current user?**

```powershell
# Check HKCU Run key (current user's startup items)
reg query HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run

# Check Task Manager startup tab
taskmgr  # → Startup tab

# Check startup folder
ls "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup"

# Check disabled startup items via registry
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run"
```

> Look for a **3rd party security app** in the disabled startup list — answer is **case sensitive**.
>

## Pentesting Uses

| Use Case | Technique |
| --- | --- |
| Enumerate SIDs | `whoami /user`, `wmic useraccount get name,sid` |
| Privilege escalation | Abuse ACEs/DACLs, access tokens, UAC bypass |
| Persistence | Run/RunOnce registry keys |
| Credential theft | Target LSA, SAM, NTUSER.DAT |
| Bypass whitelisting | AppLocker misconfigurations, LOLBins |
| Bypass Defender | Obfuscation, in-memory execution, exclusions |
| Enumerate startup items | HKCU/HKLM Run keys, Startup folder |
| Check AV status | `Get-MpComputerStatus` |

---

## Key Takeaways

- **SID** = unique identifier for every security principal; RID distinguishes accounts.
- **SAM + ACE + ACL** = access control backbone; **access tokens** validated by **LSA**.
- **UAC** = consent prompts for admin actions; bypassable but raises the bar.
- **Registry** = hierarchical database; **Run/RunOnce keys** = persistence goldmine.
- **AppLocker** = Microsoft's whitelisting; rules based on publisher, path, hash.
- **Local Group Policy** (`gpedit.msc`) = lock down individual machines.
- **Windows Defender** = strong built-in AV; still bypassable, but not a silver bullet.
- **Defense-in-depth** = configuration + patch management, not just AV.
