1. **Extracted the firmware**
    
    ```bash

    ```
    
    This extracted the SquashFS filesystem.
    
2. **Searched for the database**
    
    ```bash

    ```
    
    This found:
    
    ```
    _IOT4.bin.extracted/squashfs-root/mnt/config.sqlite
    ```

3. **Identified the relevant database table**
    
    From the extracted strings/schema, we saw the `NetworkSettings` table contains:

    - `IPAddr`

5. We then look for the **DSP-W215** row and take its `IPAddr` as the answer.

So the basic process was:

**IOT4.bin → extract filesystem → find `config.sqlite` → query `NetworkSettings` → find DSP-W215 → get its IP address.**

Sure. For **Challenge 20**, the process was:

### 1. Understand what the challenge asks

The challenge asks:

> What is the **GCC version** used to compile the file at offset `464A28` in `IoT5.bin`?
> 

So we need to inspect the data located at that offset and look for compiler information.

### 2. Identify the extracted file

Binwalk had already extracted the data from `IoT5.bin`, giving us:

```
_IOT5.bin.extracted/464A28
```

Here, `464A28` represents the **hexadecimal offset** where the file/data was found inside the firmware.

### 3. Use `strings`

The extracted file is a binary, so running `cat` wouldn't give useful readable output.

We used:

```bash
strings _IOT5.bin.extracted/464A28
```

`strings` scans a binary and extracts sequences of printable characters.

This is useful because compiled binaries often contain metadata such as:

- Linux kernel version
- GCC/compiler version
- build date
- architecture information
- library names
- error messages

### 4. Search specifically for GCC

Instead of looking through everything, we piped the output into:

```bash
grep -i 'GCC'
```

So the complete command was:

```bash
strings _IOT5.bin.extracted/464A28 | grep -i 'GCC' | head
```

Breakdown:

```
strings
   ↓
Extract readable text from binary

|
   ↓
Pass that text to grep

grep -i 'GCC'
   ↓
Search for "GCC", ignoring case

head
   ↓
Show only the first few matching lines
```

### 5. We found the compiler information

The output contained:

```
gcc version 4.3.1 20080521 (prerelease)
...
(GCC 4.3.1 Axis release R11/1.1)
```

The important part is:

```
gcc version 4.3.1
```

Therefore:

### ✅ Challenge 20 Answer: `4.3.1`

**In one sentence:** We extracted readable strings from the binary at offset `464A28`, searched those strings for GCC metadata, and found that the file was compiled using **GCC 4.3.1**.

Here's the full command sequence to reproduce the finding from scratch, in order:

```bash
# 1. Extract the firmware filesystem
binwalk -e IOT6.bin

# 2. Move into the extraction directory
cd _IOT6.bin-0.extracted

# 3. Confirm the extracted squashfs root exists
ls

# 4. Identify the board/model config baked into the build
cat squashfs-root/userfs/profile.cfg | grep -i "AYECOM_"
```

This confirms the model:

```
AYECOM_MODELNAME="D6000"
AYECOM_HWID="NETG01"
```

```bash
# 5. Find the script that maps product name -> real runtime HWID
find squashfs-root -iname "*presetting*"

# 6. Read it to get the actual HWID mapping table
cat squashfs-root/usr/script/product_presetting.sh
```

That last command reveals the mapping block:

```bash
elif [ "$1" = "D6000" ] ; then
        $SYSCMD hwid NETG0100
```

**Answer for D6000: `NETG0100`**
