## Reviewing Server python file

Port 1515 — custom LPD-style service

Source ([server.py](http://server.py/)) reviewed. It's a hand-rolled RFC 1179 receiver. Two issues identified:

Bug 1 — queue validation logic flaw

pythonif queue not in VALID_QUEUE:

VALID_QUEUE is a plain string from an env var, so this is a substring check, not membership check — sending the known queue name archive_intake should pass validation.

Bug 2 — command injection (the real vuln)

pythonsubprocess.Popen(f"echo 'Archive: {job_name}' >> /tmp/archive.log", shell=True)

job_name is taken unsanitized from a J-prefixed line in attacker-controlled submitted content, then interpolated into a shell=True command string. Closing the quote and chaining a command yields arbitrary command execution as the service's user, e.g.:

J'; id > /tmp/pwned; echo '

Protocol shape (reverse-engineered from source):

Connect → send \x02 + archive_intake (command byte 2 = "receive print job" + queue name)
Loop: send a chunk where chunk[0] is a subcommand byte and chunk[1:] is "<size> <rest>"; server reads size bytes as file content
A line starting with J inside that content becomes job_name — the injection point
Server acks with \x00 a few times, then drains further input
